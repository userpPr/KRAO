# Техническая документация проекта «Тез татым | Ашкана POS»

Ниже представлена полная документация системы, подготовленная для передачи заказчику.

### 1. Общий обзор проекта и его назначение
Проект представляет собой современный web-ориентированный POS-терминал (Point of Sale) для автоматизации работы кассира в заведениях общественного питания. Система предназначена для быстрого формирования чеков, управления заказами, работы со столами и оформления онлайн-заказов на доставку. Главная архитектурная особенность — полная интеграция с экосистемой Google (Google Sheets выступает в роли базы данных и системы управления меню), что делает продукт бесплатным в обслуживании и устойчивым к нагрузкам.

### 2. Стек технологий и зависимости
*   **Фронтенд:** Чистый HTML5, CSS3 (с использованием CSS-переменных и Flexbox/Grid для адаптивности) и Vanilla JavaScript (ES6+) без использования тяжеловесных фреймворков.
*   **Бэкенд и База Данных:** Google Apps Script (GAS) и Google Sheets.
*   **Связь:** Асинхронные запросы `fetch` (GET для получения меню, POST для сохранения заказов в режиме `no-cors` для обхода ограничений браузера).
*   **Внешние API:** WhatsApp (через генерацию ссылок `wa.me`).

### 3. Структура базы данных и обмен данными (Google Sheets)
Таблица Google выполняет двойную функцию:
1.  **Лист «Заказы» (Лист 1):** Хранит историю всех операций. Поля (столбцы): Дата, Время заказа, Номер чека (уникальный ID), Блюда (список позиций с количеством), Итого к оплате, Пометка (номер стола или данные WhatsApp).
2.  **Лист «ЦеныНаБлюда»:** Выполняет роль CMS (системы управления контентом). Поля: Категория, Название блюда, Цена. Бэкенд считывает эти данные и передает на фронтенд. 

### 4. Функционал фронтенда (Интерфейс и бизнес-логика)
*   **Динамический рендер меню:** При запуске приложения скрипт `script.js` отправляет GET-запрос к бэкенду. На основе полученных данных автоматически генерируются категории и кнопки блюд. 
*   **Управление корзиной:** Добавление блюд (с группировкой одинаковых позиций), ручное изменение количества через `input`, удаление конкретных позиций крестиком и полная очистка чека.
*   **Валидация данных:** Защита полей ввода количества от отрицательных чисел и пустого ввода (возврат к значению `1`). Строгая проверка номера телефона при отправке в WhatsApp (формат `996XXXXXXXXX`) и обязательность заполнения адреса доставки.
*   **Визуальный отклик (UI/UX):** Анимация вибрации кнопок при нажатии, эффект зачеркивания блюд (стоп-лист) по клику на карточку, салют (конфетти) и полноэкранное уведомление при успешном заказе.
*   **Модальные окна:** Изолированные окна для вывода статического QR-кода оплаты (на кассе) и отдельная форма сбора данных для онлайн-заказа.

### 5. Функционал бэкенда (Google Apps Script)
*   **Обработчик `doGet`:** Принимает запрос от кассы, находит лист «ЦеныНаБлюда», парсит его в массив объектов JSON и одновременно вычисляет номер следующего чека (`getLastRow()`), после чего отдает эти данные на фронтенд.
*   **Обработчик `doPost`:** Принимает данные сформированного чека (товары, сумма, пометки). 
*   **Защита от коллизий (`LockService`):** При записи заказа бэкенд создает цифровую очередь. Если два кассира нажимают оплату одновременно, скрипт блокирует таблицу на несколько секунд, записывает первый заказ, присваивает ему номер, затем разблокирует и записывает второй, исключая дублирование чеков.

### 6. Модуль WhatsApp (Онлайн-заказы)
При нажатии «Онлайн-заказ» вызывается специальное модальное окно. Кассир вводит адрес и номер клиента. Скрипт генерирует форматированный текстовый чек (с использованием символов `*` для жирного шрифта) и формирует URL `wa.me/996...`. При отправке в браузере открывается чат WhatsApp с готовым текстом, на экране кассира появляется QR-код для ручного прикрепления (из-за ограничений WhatsApp API на прямую передачу картинок), а в Google Sheets отправляется заказ с пометкой адреса и номера клиента.

### 7. Алгоритмы расчёта
Сумма заказа (`total`) пересчитывается динамически с помощью метода `reduce`, который умножает цену каждого блюда на его количество (`item.price * item.quantity`) и суммирует итоговое значение при любом изменении состава корзины. 

### 8. Обработка ошибок и резервные сценарии (Fallbacks)
Система спроектирована с учетом возможных сбоев связи. Запрос на получение цен обернут в блок `try...catch`. Если сервер Google не отвечает, отсутствует интернет или лист «ЦеныНаБлюда» удален, срабатывает блок `catch`, который загружает резервный массив данных `fallbackMenu` (вшитый в код), переводит индикатор статуса в красный цвет и позволяет кассе продолжить работу в оффлайн-режиме.
